# Plan 02-03: Task Classification Router, VRAM-Aware Scheduler & Dynamic Swapping Engine

## Objective

Build the task-to-model auto-router and the GPU VRAM-aware dynamic scheduler for the Sovereign AI Workbench. Implement `TaskRouter` to automatically classify incoming user prompts and data payloads into required capabilities (`text_drafting`, `code_generation`, `vision_multimodal`, `calculation`, `embedding`), selecting the optimal model while respecting manual overrides (`--model`). Implement `VRAMScheduler` to track memory budgets on a reference 24GB-class GPU, prevent out-of-memory (OOM) crashes via LRU model eviction and dynamic swapping, and log all routing and scheduling transitions to the cryptographic audit ledger.

## User Story Framing

**As an** industrial engineer or plant technician,  
**I want** the workbench to automatically select the right specialized model for my task and dynamically manage GPU memory so that complex multi-step workflows (such as vision inspection followed by code generation) never crash the system with out-of-memory errors,  
**So that** I receive expert-level results without needing to manually manage model loading or server VRAM.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V14.2 (Dependency Configuration), V8.1 (General Data Protection).
- **Threat T-02-02 (STRIDE: Denial of Service):** A sequence of concurrent or heavy multi-model tasks causes GPU memory exhaustion, crashing the inference backend or freezing the host server.
  - *Mitigation:* `VRAMScheduler` tracks real-time and declared VRAM usage against a hard ceiling (24,576 MB default, with a 2,048 MB safety headroom reserve). If an incoming model would exceed budget, the scheduler atomically unloads idle models in LRU order before loading the new model.
- **Threat T-02-06 (STRIDE: Repudiation):** A user or auditor questions why a specific model was chosen for an engineering calculation or report.
  - *Mitigation:* Every routing decision and model swap is recorded in the Phase 1 `AuditLedger` as `MODEL_ROUTED`, `MODEL_LOADED`, and `MODEL_SWAPPED` events, capturing the task classification score, input length, and selection rationale.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `MODL-02`: System automatically routes incoming user tasks to appropriate model class (reasoning/drafting, code execution, vision/multimodal) based on task classification (FR-MM-2).
  - `MODL-03`: Model manager tracks GPU VRAM usage and orchestrates model loading/unloading or graceful quantization to prevent out-of-memory crashes on single 24GB-class GPU (FR-MM-3).
- **Locked Decisions Implemented:**
  - `D-24`: Multi-Tier Task Classification Router with Deterministic Rule Heuristics and Manual Override (`--model <id>`).

  - `D-26`: Comprehensive Audit Logging for Routing and Memory Transitions (`MODEL_ROUTED`, `MODEL_SWAPPED`).
  - `D-27`: Built-in Routing CLI (`sovereign model route "<prompt>"`).

    - Thread-safe / concurrency-safe state transitions guarded by an internal lock.

  <action>
    Implement `src/sovereign/models/scheduler.py` containing `VRAMScheduler`.
    Configure budget parameters: `total_vram_mb = 24576`, `reserve_headroom_mb = 2048`, leaving `usable_vram_mb = 22528`.
    Implement memory accounting:
    - If discrete GPU is present and PyNVML / torch is available, query real-time GPU free memory.
    - Otherwise, maintain rigorous deterministic simulated VRAM tracking based on `manifest.vram_estimate_mb`.
    In `ensure_loaded(model_id)`:
    1. If model already loaded, update its `last_used_timestamp` and return adapter.
    2. Check if `manifest.vram_estimate_mb > usable_vram_mb`: raise `VRAMExceededError`.
    3. While `current_allocated + manifest.vram_estimate_mb > usable_vram_mb`:
       Find least recently used (LRU) model among currently loaded models (excluding active task locks).
       Call `adapter.unload()`. Subtract its VRAM from `current_allocated`.
       Log `MODEL_UNLOADED` and `MODEL_SWAPPED` to `AuditLedger`.
    4. Call `target_adapter.load()`. Add its VRAM to `current_allocated`.
    5. Log `MODEL_LOADED` to `AuditLedger`.
    6. Return `target_adapter`.
    Write integration tests in `tests/test_models/test_vram_scheduler.py` testing concurrent loads, sequential swaps, LRU eviction order, memory budget boundaries, and audit log generation.
