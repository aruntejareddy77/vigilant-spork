# Plan 04-04: Engineering Drawing / P&ID Revision Comparison & Visual Annotation Overlay Generator

## Objective

Implement the sovereign computer vision and engineering drawing comparison pipeline for the Sovereign AI Workbench. Build `DrawingDiffEngine` executing a dual-layer differencing architecture: Layer 1 performs pure-Python pixel differencing, morphological thresholding, and connected bounding contour extraction via Pillow; Layer 2 leverages local vision-language reasoning via `BaseModelAdapter.vision_infer()` to extract semantic descriptions of modified equipment tags, valves, and piping connections. Render high-contrast visual annotation overlay images adhering to industrial drafting conventions (Green for Added, Red for Removed, Amber for Modified) with numbered callout badges and an engineering title block with legend. Export a structured Change Register table (.docx, Markdown, JSON) and bind the comparison engine into the tool registry as `diff_drawings`.

## User Story Framing

**As a** plant piping and instrumentation (P&ID) engineer or project manager,  
**I want** to upload two revisions of an engineering drawing or schematic and receive an annotated visual overlay highlighting physical differences alongside a structured change register,  
**So that** changes between revisions (new valves, decommissioned bypass lines, relocated instrumentation) are identified instantly without tedious manual line-by-line drawing inspection.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V5.1 (Input Validation), V5.2.4 (Memory Bounds), V10.3 (Application Integrity).
- **Threat T-04-03 (STRIDE: Denial of Service):** Uploading extremely large rasterized engineering drawings (e.g., $60,000 \times 60,000$ pixels) causes out-of-memory crashes during multi-layer image diffing or VLM thumbnail extraction.
  - *Mitigation:* Strict dimension and memory verification. Enforce `PIL.Image.MAX_IMAGE_PIXELS = 50_000_000`. Validate file formats (`image/png`, `image/jpeg`, `image/tiff`) and auto-scale drawing dimensions exceeding 4096px on any side using bilinear downsampling before pixel differencing buffers are allocated, ensuring memory allocation remains bounded under 250MB.
- **Threat T-04-04 (STRIDE: Tampering):** Path traversal when saving generated overlay images or change register tables outside the designated `/local/output` directory.
  - *Mitigation:* Strict Path Fencing. Enforce workspace path validation with `Path(output_path).resolve().is_relative_to(output_directory)` on all rendered image and report outputs.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `MMOD-03`: Vision model analyzes engineering drawings, P&IDs, and equipment photographs to extract structural descriptions and visual elements (FR-MI-3).
- **Research Decisions Implemented:**
  - Dual-layer differencing: Layer 1 pure Pillow pixel differencing and contour bounding box extraction; Layer 2 local VLM semantic inference.
  - High-contrast visual overlay conventions: Desaturated monochrome background base (`#808080`), Green (`#00C853`) for Added, Red (`#D50000`) for Removed, Amber (`#FFD600`) for Modified, with 15% opacity fills.
  - Solid numbered circular callout badges cross-referenced against the structured Change Register.
  - Complete reliance on pure Pillow (PIL) and local model adapters without heavy external OpenCV (`cv2`) dependencies.
  - Delivery of output overlay with injected PNG lineage metadata and companion change register table.

### Truths
- Drawing differencing operates 100% locally on standard image formats (PNG, JPEG, TIFF) without proprietary CAD vector software or external cloud vision APIs.

- Overlay visual rendering follows industrial conventions: desaturated base background, Green for Added, Red for Removed, Amber for Modified, and numbered callouts.
- Every change is cross-referenced between the visual overlay and the textual Change Register.
