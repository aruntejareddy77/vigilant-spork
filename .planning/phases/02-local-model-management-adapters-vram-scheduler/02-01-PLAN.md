# Plan 02-01: Uniform Model Manager Interface, Manifest Registration Schema & Model Registry

## Objective

Establish the core model abstraction and catalog foundation for the Sovereign AI Workbench. Implement the declarative `ModelManifest` schema supporting local open-weight model registration via YAML/JSON, the abstract `BaseModelAdapter` interface defining uniform generation, embedding, and vision methods, and the runtime `ModelRegistry` providing capability-based indexing and hot-registration without service restarts. Expose model inspection and registration commands via the sovereign CLI.

## User Story Framing

**As an** industrial AI systems engineer or plant operator,  
**I want** to register and configure local open-weight models using declarative manifest files without changing any orchestrator or application code,  
**So that** the workbench can adapt to new model releases, quantized weights, and specialized industrial models seamlessly and securely.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V10.3 (Application Integrity), V14.2 (Dependency Configuration).
- **Threat T-02-01 (STRIDE: Tampering):** An attacker or corrupted update injects a malicious model manifest pointing to unverified binaries, malicious local endpoints, or backdoored weight files.
  - *Mitigation:* `ModelManifest` schema validates all paths, requires explicit `weights_sha256`, enforces loopback-only IP endpoints (`127.0.0.1` or `localhost`), and validates file integrity against Phase 1's `AttestationGuard` before registration.
- **Threat T-02-03 (STRIDE: Elevation of Privilege):** Subprocess injection via untrusted model paths or arbitrary execution arguments.
  - *Mitigation:* `ModelManifest` strictly limits path resolution to configured directories and rejects shell interpolation arguments.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `MODL-01`: System provides a pluggable adapter interface supporting local open-weight model registration via YAML/JSON manifest without modifying orchestrator code (FR-MM-1).
- **Locked Decisions Implemented:**
  - `D-17`: Declarative YAML/JSON Model Manifest with Capabilities, VRAM Estimates & Weights SHA-256 (`model_manifest.yaml`).
  - `D-18`: Abstract `BaseModelAdapter` Uniform Interface decoupling orchestrator from engine implementations.
  - `D-19`: Dynamic In-Memory `ModelRegistry` with Runtime Hot-Add (FR-MM-4) and Capability-Based Filtering.
  - `D-20`: Built-in Model CLI Subcommands (`sovereign model list / inspect / register`).
