# Plan 04-01: Offline OCR and Structured Form Handwriting Extraction Pipeline

## Objective

Build the sovereign offline multimodal document ingestion pipeline for the Sovereign AI Workbench. Implement an extensible, zero-network OCR engine architecture (`BaseOCRBackend`, `TesseractOCRBackend`, and `DeterministicMockOCRBackend`) that extracts text, layouts, and bounding boxes from scanned and photographed documents without external API calls. Implement `FormExtractor` to parse structured inspection checklists, checkboxes, and handwritten entries with confidence scoring, automatically flagging entries below the mandatory 0.85 threshold to trigger Human-in-the-Loop (`interrupt()`) verification. Normalize all multimodal inputs into a unified schema (`NormalizedDocument`) preserving page indices, normalized 2D spatial coordinates (`[ymin, xmin, ymax, xmax]`), and stable region IDs for cryptographic auditability and deliverable citations.

## User Story Framing

**As an** industrial inspection engineer or plant safety auditor,  
**I want** to ingest paper inspection checklists, scanned equipment reports, and handwritten logs completely offline,  
**So that** textual content, tabular data, and handwritten entries are converted into structured, normalized representations with explicit confidence scores, and low-confidence readings are flagged for my manual sign-off before being incorporated into official plant records.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V5.1 (Input Validation), V5.2.4 (Memory Bounds), V10.3 (Application Integrity).
- **Threat T-04-03 (STRIDE: Denial of Service):** Malicious or corrupted image upload (decompression bomb / pixel bomb, e.g., $100,000 \times 100,000$ pixels) causes catastrophic host memory exhaustion during OCR processing or rendering.
  - *Mitigation:* Enforce `PIL.Image.MAX_IMAGE_PIXELS = 50_000_000` (capping decompressed allocation at ~200MB). Validate image headers, mime-types (`image/png`, `image/jpeg`, `image/tiff`, `application/pdf`), and file size ceilings (max 50MB per file, max 100 pages per PDF). Reject any input violating limits with `InvalidDocumentError`.
- **Threat T-04-05 (STRIDE: Elevation of Privilege):** OCR misreads a critical flange thickness measurement (e.g., $1.2\text{ mm}$ read as $12.0\text{ mm}$), silently approving an out-of-spec or corroded asset in an official approval memo.
  - *Mitigation:* The `FormExtractor` computes a field-level confidence metric $c \in [0.0, 1.0]$. Any field with $c < 0.85$ is marked `needs_review=True`. When processed by the agent orchestration state machine, this condition immediately raises `GraphInterrupt`, halting automated generation until explicit operator sign-off is recorded.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `MMOD-01`: Offline OCR pipeline extracts text, layout, and bounding boxes from scanned/photographed documents (FR-MI-1).
  - `MMOD-02`: Handwriting recognition extracts entries from structured inspection checklists and forms with confidence scoring and flagging for low confidence (FR-MI-2).
  - `MMOD-04`: System normalizes ingested content into a unified representation preserving page numbers and region coordinates for citation (FR-MI-4).
- **Research Decisions Implemented:**
  - Pluggable OCR backend architecture with pure-Python `DeterministicMockOCRBackend` enabling 100% test pass on headless, GPU-less, and binary-less CI environments.
  - Mandatory confidence threshold $\tau_{\text{conf}} = 0.85$ with `needs_review` flagging integrated into Phase 3 HITL approval flow.
  - Unified `NormalizedDocument` schema with normalized 2D bounding boxes $[0.0, 1.0]$ and canonical RFC 8785 JSON serialization.
  - Strict path fencing on input files to prevent directory traversal.
