# Plan 05-01: FastAPI Backend Service, REST APIs, WebSocket Event Streaming & 3-Tier RBAC Middleware

## Objective

Build the central, air-gapped FastAPI backend service for the Sovereign AI Workbench. Implement strict socket binding security guards that fail closed on `0.0.0.0`, IPv6 all-interfaces `::`, or unauthorized public IPs, validating binding exclusively against loopback (`127.0.0.1`) and declared enterprise intranet CIDRs from `network_policy.yaml`. Implement `HostHeaderMiddleware` to defend against DNS rebinding attacks. Construct a 3-tier Role-Based Access Control (RBAC) middleware and dependency injection system enforcing least-privilege access across Admin, Engineer, and Auditor roles. Ensure that the Auditor role is strictly blocked from task submission (`POST /api/tasks`, `POST /api/demos/*`) and workflow resumption (`POST /api/tasks/{id}/resume`) with HTTP 403 Forbidden, and that any unauthorized attempt immediately logs an immutable `SECURITY_ALERT_RBAC_VIOLATION` event in the cryptographic `AuditLedger`. Implement a multi-channel WebSocket streaming manager for real-time agent reasoning traces, network socket telemetry, and Human-in-the-Loop (HITL) approval gate alerts. Expose complete REST APIs for tasks, models, VRAM metrics, network policy/telemetry, audit ledger verification, document preview, and guided demonstration triggers with CORS restricted to intranet/localhost.

## User Story Framing

**As an** industrial systems security officer and plant operations engineer,  
**I want** a secure, high-performance local backend gateway that binds strictly to authorized intranet/loopback interfaces and cryptographically enforces 3-tier role permissions,  
**So that** engineers can submit tasks and approve deliverables, auditors can independently inspect audit logs and live network egress telemetry without any ability to alter operational workflows, and external or unapproved network interfaces cannot access the platform.

### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Categories:**
  - V1.4.1 (Access Control Architecture): Least-privilege role separation enforced at the middleware layer.
  - V4.1.1 (Access Control Enforcement): Every API endpoint explicitly verifies user clearance level prior to dispatching business logic.
  - V5.1.3 (Input Validation): All incoming REST and WebSocket payloads validated via strict Pydantic schemas with `extra="forbid"`.
  - V13.1.1 (Generic Web Service Verification): Explicit host header validation prevents DNS rebinding; CORS is restricted to loopback and configured intranet origins.

- **Threat T-05-01 (STRIDE: Elevation of Privilege / Tampering):** Dual-homed engineering laptop connects to both an internal air-gapped industrial SCADA network and an external corporate intranet. Server binds to `0.0.0.0`, allowing unauthorized corporate users or malware on the external NIC to submit tasks, exfiltrate schematics, or bypass air-gap controls.
  - *Mitigation:* `validate_server_binding()` executes on server initialization and halts startup immediately with `BindingSecurityError` if host is `0.0.0.0`, `::`, or outside `NetworkPolicyEngine.allowed_intranet`.

- **Threat T-05-02 (STRIDE: Spoofing):** Attacker crafts malicious local DNS resolver or browser script using DNS rebinding to send cross-origin requests to `http://127.0.0.1:8000` from an external domain name.
  - *Mitigation:* `HostHeaderMiddleware` validates incoming `Host` headers against an explicit allowlist (`localhost`, `127.0.0.1`, and configured server intranet IP), rejecting spoofed host headers with HTTP 400 Bad Request.

- **Threat T-05-03 (STRIDE: Elevation of Privilege):** An Auditor-role user bypasses the Web UI and directly executes `curl -X POST http://127.0.0.1:8000/api/tasks` or calls the resume endpoint to approve a deliverable.
  - *Mitigation:* FastAPI dependency injection `require_role(UserRole.ENGINEER)` guards all mutating endpoints. The middleware extracts the role from the cryptographically verified token or secure session header, rejects the Auditor with HTTP 403 Forbidden, and triggers a `SECURITY_ALERT_RBAC_VIOLATION` event recorded in the tamper-evident `AuditLedger`.

- **Threat T-05-04 (STRIDE: Tampering / Injection):** Malicious task submission payload contains extra unexpected parameters, invalid JSON, or path traversal strings attempting to manipulate the filesystem or sandbox.
  - *Mitigation:* Pydantic request models enforce strict field typing and schema boundaries (`extra="forbid"`), and file paths are validated against allowed workspace boundaries using `Path.resolve()`.

- **Threat T-05-05 (STRIDE: Denial of Service):** Fast WebSocket telemetry producer overloads a slow client, causing unbounded in-memory event queues and exhaustion of host RAM.
  - *Mitigation:* `ConnectionManager` utilizes bounded `asyncio.Queue` (max 200 items per connection) with non-blocking enqueue that drops stale telemetry events if the client falls behind, while canonical history remains safely preserved in `ConnectionRingBuffer`.
</threat_model>

  - Fail-closed network binding validation guard rejecting `0.0.0.0` and verifying LAN IPs against `network_policy.yaml`.

  - Cryptographic token format (`sovg_<role>_<random>_<hmac>`) with fallback to `X-Sovereign-Role` in development/kiosk mode.

### Truths
- The backend server binds strictly to `127.0.0.1` or declared intranet CIDRs, failing closed on `0.0.0.0` or public IPs.

- The Auditor role is strictly prohibited from submitting tasks or resuming approval gates, returning HTTP 403 Forbidden and logging a security violation in the audit ledger.
