# Plan 02-02: Local Inference Adapters (SGLang, vLLM, Ollama, llama.cpp) & Deterministic Mock Adapter

## Objective

Implement production-grade local model inference adapters conforming to `BaseModelAdapter`. Build a comprehensive, deterministic `MockModelAdapter` enabling 100% offline testing without discrete GPU hardware (supporting text, chat, schema-guided JSON, embeddings, and vision region detection). Implement the `LocalHTTPModelAdapter` and specialized engine adapters (`SGLangAdapter`, `VLLMAdapter`, `OllamaAdapter`, `LlamaCppAdapter`) communicating over loopback HTTP sockets with robust timeout and error handling. Provide an adapter factory dynamically instantiating backends from manifest definitions.

## User Story Framing

**As an** industrial AI application developer or CI/CD test runner,  
**I want** deterministic mock adapters that simulate multi-modal model execution with zero GPU requirements, and standardized local engine adapters for production SGLang/vLLM/Ollama runtimes,  
**So that** the entire workbench pipeline can be validated on commodity developer laptops and seamlessly deployed onto GPU server hardware in air-gapped industrial facilities.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V14.2 (Dependency Configuration), V1.4 (Access Control Architecture).
- **Threat T-02-04 (STRIDE: Information Disclosure / Egress):** An adapter attempts to communicate with external cloud endpoints (e.g. OpenAI or Hugging Face) instead of strictly local loopback runtimes.
  - *Mitigation:* Adapters enforce strict loopback address checks (`127.0.0.1` or `localhost`). Any attempted outbound HTTP call to non-loopback addresses triggers an immediate `SecurityException` and logs an alert to `AuditLedger`.
- **Threat T-02-05 (STRIDE: Denial of Service):** An inference engine hangs indefinitely or crashes, blocking orchestrator worker threads.
  - *Mitigation:* All HTTP requests enforce strict configurable timeouts (connect and read timeouts) and return structured error codes rather than blocking indefinitely.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `MODL-01`: System provides a pluggable adapter interface supporting local open-weight model registration via YAML/JSON manifest without modifying orchestrator code (FR-MM-1).
  - `MODL-04`: System supports a deterministic test/mock model adapter allowing full end-to-end verification in environments without discrete GPU hardware.
- **Locked Decisions Implemented:**
  - `D-21`: Deterministic In-Memory Mock Model Adapter (`MockModelAdapter`) supporting text, chat, JSON, embeddings, and vision.
  - `D-22`: Standardized Localhost HTTP Protocol Adapter (`LocalHTTPModelAdapter`) for SGLang, vLLM, Ollama, and llama.cpp.
  - `D-23`: Adapter Factory Pattern dynamically mapping `manifest.engine.type` to concrete adapter classes.
