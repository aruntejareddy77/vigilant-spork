# Plan 01-01: Cryptographic Audit Ledger & Verification Engine

## Objective

Build the tamper-evident cryptographic audit subsystem for the Sovereign AI Workbench. Implement an append-only JSONL ledger (`audit_ledger.jsonl`) employing strict RFC 8785 canonical JSON hashing and SHA-256 hash-chaining, backed by a synchronous SQLite query mirror (`audit_index.sqlite`) in WAL mode for fast session filtering, and protected by a dual verifier (CLI diagnostic tool + startup/pre-write runtime guard).

## User Story Framing

**As an** industrial compliance officer or security auditor,  
**I want** every system action, agent decision, tool execution, and deliverable generation to be permanently recorded in a cryptographically chained, tamper-evident audit ledger with sub-millisecond query capabilities,  
**So that** any post-hoc tampering, log deletion, or fraudulent modification is mathematically detectable and verifiable offline.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V8.1 (General Data Protection — Cryptographic Audit Trail), V1.4 (Access Control Architecture).
- **Threat T-01-01 (STRIDE: Spoofing):** Rogue or unprivileged processes inject forged audit records or corrupt concurrent ledger writes.
  - *Mitigation:* Apply cross-platform OS advisory file locking (`portalocker.Lock`) on ledger writes, enforce strict Pydantic schema validation, and bind caller role and session IDs into canonical hashes.
- **Threat T-01-02 (STRIDE: Tampering):** Malicious insiders or compromised agent tools modify, delete, or reorder historical audit entries to conceal unauthorized actions.
  - *Mitigation:* Hash chaining over strict RFC 8785 canonical JSON representations. Modifying any byte alters the SHA-256 entry hash and invalidates every subsequent block. The runtime tip guard halts writes, and `sovereign audit verify` pinpoints the corrupted record.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `SOVG-01`: Append-only structured local audit log records every agent step, tool call, model invocation, user action, and output file.
  - `SOVG-02`: Audit log entries are cryptographically hash-chained (SHA-256) such that tampering or deletion is immediately detectable.
- **Locked Decisions Implemented:**
  - `D-01`: Dual Storage: Append-Only JSONL Ledger (`audit_ledger.jsonl`) + SQLite Query Mirror (`audit_index.sqlite`).
  - `D-02`: Strict RFC 8785 Canonical JSON Hashing (SHA-256 over exact 7 fields).
  - `D-03`: Continuous Global Ledger with Session-Tagged Streams.
  - `D-04`: Dual Verifier & Runtime Guard (`sovereign audit verify` + startup/pre-write tip hash guard).
