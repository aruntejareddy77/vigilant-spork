# Plan 03-02: Tool Registry with JSON Schema, RBAC Clearance & Built-in Industrial Tools

## Objective

Build the rigid tool registry and safe built-in execution suite for the Sovereign AI Workbench. Implement `ToolRegistry` generating standard JSON Schemas for LLM tool calling, enforcing Role-Based Access Control (Admin, Engineer, Auditor), and dispatching calls. Implement secure built-in industrial tools for fenced filesystem operations (`read_file`, `write_file`, `list_directory` strictly bounded to a designated workspace directory to prevent traversal), structured document/table parsing (`parse_table`, `extract_text`), and safe mathematical calculation (`execute_calculation` via AST expression parsing with formula traces, strictly avoiding `eval`).

## User Story Framing

**As an** industrial AI system administrator,  
**I want** tools to be registered with strict JSON Schema definitions, RBAC role requirements, and workspace path fences,  
**So that** AI agents can reliably call specialized capabilities without threatening host filesystem integrity or exceeding operator privileges.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V12.3 (File Execution), V1.4 (Access Control Architecture), V5.1 (Input Validation).
- **Threat T-03-04 (STRIDE: Elevation of Privilege / Tampering):** An agent or prompt injection attempts path traversal attacks (`../../etc/shadow` or `..\..\Windows\System32`) through filesystem tools.
  - *Mitigation:* Filesystem tools (`read_file`, `write_file`, `list_directory`) resolve all target paths against a canonicalized `workspace_root` directory. If the resolved path does not start with `workspace_root`, the tool throws an immediate `PathSecurityViolation` and logs a security alert.
- **Threat T-03-07 (STRIDE: Elevation of Privilege):** An unprivileged user or agent invokes an administrative tool without clearance.
  - *Mitigation:* `ToolRegistry` validates the caller's `UserRole` against `tool.required_role` before execution. If clearance is insufficient, execution is rejected with `PermissionDeniedError`.
- **Threat T-03-08 (STRIDE: Remote Code Execution):** Mathematical calculation tool uses dangerous `eval()` allowing arbitrary Python execution.
  - *Mitigation:* The calculation engine uses Python's Abstract Syntax Tree (`ast`) to evaluate only safe mathematical nodes (Add, Sub, Mult, Div, Pow, Call to approved math functions), completely rejecting statements, imports, or variable assignments.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `TOOL-01`: Tool registry defines explicit JSON Schema specifications for every available tool used for structured invocation (FR-AO-2).
  - `TOOL-03`: Built-in tools support file operations (read, write, list), structured document parsing (tables, text), and mathematical calculations with auditable formula traces.
- **Locked Decisions Implemented:**
  - `D-32`: Rigid JSON Schema Tool Registry with declared RBAC role clearance (Admin/Engineer/Auditor) and workspace filesystem path fencing.
  - `D-33`: Built-in tools: `read_file`, `write_file`, `list_directory`, `parse_table`, `extract_text`, `execute_calculation`.
