# Plan 06-01: Sample Datasets, Test Fixtures & Automated Demo Test Suite

## Objective

Programmatically synthesize, package, and validate deterministic industrial sample assets (`samples/`) for the Sovereign AI Workbench, and construct a high-fidelity automated test harness (`tests/test_demos/`) covering all three Smart India Hackathon (SIH) core demonstration workflows. Implement standalone asset generation in `scripts/generate_sample_assets.py` producing a high-resolution simulated inspection report scan (`refinery_vessel_inspection_v301.png`), a 10,000-row vibration and thermal sensor historian export (`historian_sensor_telemetry.csv`), and dual-revision P&ID engineering drawings (`pid_drawing_rev_a.png` and `pid_drawing_rev_b.png`). Build comprehensive automated integration test suites for Demo A (scanned document OCR, confidence thresholding, HITL approval gate, and styled Word export with scan citations), Demo B (industrial code generation, isolated zero-network CodeSandbox execution, seeded KeyError auto-fix recovery loop, and runnable artifact bundling), and Demo C (P&ID revision comparison, Layer 1 spatial differencing, visual overlay rendering, and change register export in docx and csv).

## User Story Framing

**As an** industrial systems evaluator, plant maintenance lead, or hackathon judge,  
**I want** authentic, deterministic sample datasets and fully automated end-to-end test suites for the three sovereign demonstration workflows,  
**So that** I can verify that the workbench ingests scanned inspection reports, generates and self-corrects industrial code, and detects engineering drawing revisions unassisted—100% offline with zero external network connectivity, zero cloud hallucinations, and complete cryptographic provenance.

### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Categories:**
  - V1.4.1 (Access Control Architecture): Least-privilege role separation enforced across task submission and HITL approvals.
  - V5.1.3 (Input Validation): Rigorous validation of image dimensions, decompression bomb ceilings (<50M pixels), and CSV format boundaries.
  - V5.2.4 (Memory & Resource Ceilings): Strict file size (<50MB) and image scaling boundaries preventing denial-of-service via resource exhaustion.
  - V5.3 (Output Sanitization): Deliverables sanitized against CSV formula injection (`=`, `+`, `-`, `@`) and Word macro injection.
  - V10.3 (Audit Trail Integrity): Unbroken SHA-256 hash chaining capturing all step transitions, tool invocations, and approval decisions.

- **Threat T-06-01 (STRIDE: Elevation of Privilege):** An unauthorized user (such as an Auditor) attempts to approve an inspection finding or trigger deliverable generation directly without required engineering authority.
  - *Mitigation:* HITL approval gate enforces `require_role(UserRole.ENGINEER)` returning HTTP 403 Forbidden on Auditor attempts, halting execution and logging a `SECURITY_ALERT_RBAC_VIOLATION` in `AuditLedger`.

- **Threat T-06-02 (STRIDE: Information Disclosure / Exfiltration):** Generated Python script in Demo B attempts socket connection or HTTP exfiltration of industrial telemetry data.
  - *Mitigation:* `validate_script_safety()` executes static AST analysis blocking network modules (`socket`, `http`, `urllib`, `requests`, `aiohttp`, `httpx`). Sandboxed execution runs with network namespace isolation (`unshare -n` on Linux) and stripped environment variables.

- **Threat T-06-03 (STRIDE: Denial of Service / Decompression Bomb):** Adversary uploads a multi-gigapixel compression bomb disguised as a scanned inspection report or P&ID drawing to exhaust server memory.
  - *Mitigation:* `validate_image_file()` sets `Image.MAX_IMAGE_PIXELS = 50_000_000`, enforces maximum file size of 50MB, forces pixel verification with `img.verify()`, and auto-scales dimensions exceeding 4096px via bilinear interpolation.

- **Threat T-06-04 (STRIDE: Tampering / CSV Formula Injection):** An attacker injects malicious spreadsheet formulas (e.g. `=cmd|' /C calc'!A0` or `@SUM(...)`) into equipment tags or inspection descriptions in change registers.
  - *Mitigation:* `ChangeRegisterGenerator` sanitizes tabular text fields, escaping or prefixing single quotes before leading formula characters (`=`, `+`, `-`, `@`), preventing formula execution in downstream spreadsheet software.

- **Threat T-06-05 (STRIDE: Path Traversal in Deliverable Export):** Export paths manipulated to escape `/local/output` and overwrite critical system binaries or sensitive configuration files.
  - *Mitigation:* `validate_output_path()` and `CodeArtifactExporter` enforce `Path(target).resolve().is_relative_to(allowed_root)`, raising `PathSecurityViolation` immediately on traversal attempts.
</threat_model>
