# Plan 04-02: Local Vector Database RAG Pipeline with RBAC Filtering & Inline Citations

## Objective

Build the local retrieval-augmented generation (RAG) knowledge engine for the Sovereign AI Workbench. Implement an offline document chunker (`DocumentChunker`) preserving physical page numbers and spatial region IDs, paired with a zero-dependency embedded SQLite vector database (`SQLiteVectorStore`) operating in Write-Ahead Log (WAL) mode to store 768-dimensional float embeddings as packed binary blobs. Implement strict SQL-level RBAC pre-filtering ensuring queries only evaluate candidate chunks cleared for the caller's role (`admin`, `engineer`, `auditor`), preventing unauthorized information disclosure and ranking denial attacks. Implement the `CitationEngine` to validate inline bracketed citations (`[Doc: <doc_id>, p.<num>#<reg>]`), format structured reference tables, and bind citations directly to deliverable cryptographic lineage manifests.

## User Story Framing

**As an** industrial facility engineer or plant compliance officer,  
**I want** to query on-premises engineering manuals, operating procedures (SOPs), and inspection logs using semantic search,  
**So that** retrieved answers cite exact source document IDs, pages, and regions, while confidential documents remain completely inaccessible to users without required clearance.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V1.4 (Access Control Architecture), V8.3 (Sensitive Data Handling in Logs), V5.1 (Input Validation).
- **Threat T-04-01 (STRIDE: Information Disclosure):** An unauthorized user (e.g. `auditor` or standard `engineer`) queries the RAG engine to retrieve chunks from confidential executive decisions or restricted plant safety manuals.
  - *Mitigation:* Mandatory SQL-Level Pre-Filtering. The `SQLiteVectorStore` executes candidate selection using `WHERE (classification IN (...) AND (allowed_roles_json IS NULL OR EXISTS (SELECT 1 FROM json_each(chunks.allowed_roles_json) WHERE json_each.value = ?)))` *before* embeddings are unpacked or similarity scores are calculated. Unauthorized vectors are never loaded into memory, evaluated, or ranked.
- **Threat T-04-06 (STRIDE: Information Disclosure):** External vector database daemons (Chroma, Qdrant) or embedding clients execute phone-home telemetry or attempt external network calls, violating default-deny egress policies.
  - *Mitigation:* The vector store is implemented strictly as an embedded SQLite database (`sovereign_knowledge.sqlite`) using WAL mode, with local embeddings generated exclusively by Phase 2 `BaseModelAdapter.embed()`. Zero background network daemons, zero telemetry calls.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `RAG-01`: System indexes designated local document folders into an on-premises vector database with offline chunking and local embeddings (FR-KB-1).
  - `RAG-02`: Agent generates answers with inline citations referencing specific document IDs and section/page locations (FR-KB-2).
  - `RAG-03`: Retrieval results are filtered dynamically by user RBAC permissions preventing unauthorized access to restricted documentation (FR-KB-4).
- **Research Decisions Implemented:**
  - Zero-dependency embedded SQLite vector store in WAL mode with packed IEEE-754 binary float blobs (`struct.pack`).
  - Exact inner dot product cosine similarity executing in $< 15\text{ ms}$ for thousands of unit-norm vectors.
  - SQL pre-filtering against `UserRole` clearance eliminating post-filtering information denial and side-channel timing attacks.
  - Inline citation format `[Doc: <doc_id>, p.<page_num>#<region_id>]` validated against indexed chunk IDs and integrated with Phase 1 `LineageEngine`.
