# Plan 05-03: Sovereign Workbench CLI & Lightweight Python SDK

## Objective

Deliver the full-featured command-line interface (CLI) and lightweight Python client SDK for the Sovereign AI Workbench. Extend the unified Click-based `sovereign` CLI with server management (`sovereign serve`), task lifecycle operations (`sovereign task submit`, `status`, `logs --follow`, `approve`, `reject`), and real-time GPU memory inspection (`sovereign model vram`). Enforce least-privilege Role-Based Access Control (RBAC) at the CLI surface, proactively blocking the Auditor role from task submission and HITL approval with an informative error message and exit code 1. Construct `sovereign.sdk`, a zero-heavy-dependency Python client library built strictly on Python standard library modules (`urllib.request`, `json`, `time`, `dataclasses`) with zero required external pip dependencies. Provide dedicated client namespaces (`client.tasks`, `client.models`, `client.network`, `client.audit`) supporting programmatic task submission, polling, artifact retrieval, GPU headroom tracking, and cryptographic audit trail verification. Ensure that SDK methods enforce RBAC permissions locally and raise `RBACPermissionError` when unauthorized actions are attempted.

## User Story Framing

**As an** automation engineer, data scientist, or platform administrator,  
**I want** a full-featured CLI and pure-Python SDK that execute seamlessly on air-gapped industrial workstations without installing external pip packages,  
**So that** I can script end-to-end task pipelines, inspect VRAM consumption, stream live agent thoughts to standard output, and verify cryptographic audit trails programmatically while strictly adhering to role permissions.

### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Categories:**
  - V4.1.1 (Access Control Enforcement): Consistent role checking enforced across CLI arguments and SDK method dispatches.
  - V5.1 (Input Validation): Safe path validation prevents directory traversal during CLI/SDK artifact downloads.
  - V14.1 (Build and Dependency Management): Zero third-party runtime dependencies in the SDK prevents software supply chain poisoning on air-gapped workstations.

- **Threat T-05-03 (STRIDE: Elevation of Privilege):** An Auditor-role operator executes `sovereign task submit "generate code"` from the command line or calls `client.tasks.submit()` in an automation script to bypass web UI restrictions.
  - *Mitigation:* The CLI parser inspects `--role` before dispatching, immediately refuses execution with exit code 1, and prints an explicit error: `[ERROR] Auditor role is restricted from submitting tasks per least-privilege policy (UI-05)`. The SDK's `client.tasks.submit()` method performs a client-side clearance assertion and translates any backend HTTP 403 response into a strongly-typed `RBACPermissionError`.

- **Threat T-05-08 (STRIDE: Tampering / Arbitrary File Overwrite):** CLI or SDK artifact download (`sovereign task download` or `client.tasks.download_artifact`) processes a crafted filename containing relative paths (e.g. `../../etc/passwd` or `..\..\Windows\System32\payload.dll`), overwriting critical host files.
  - *Mitigation:* Both CLI and SDK resolve destination paths strictly within the designated target directory using `Path.resolve()` and verify `target_file.is_relative_to(output_dir)`, raising `ValueError` or `SecurityError` on any escape attempt.

- **Threat T-05-09 (STRIDE: Supply Chain / Denial of Service):** Deploying the Python SDK on air-gapped field laptops fails because the SDK requires external dependencies (e.g., `requests`, `aiohttp`, `pydantic`) not present on locked-down client machines.
  - *Mitigation:* `sovereign.sdk` uses zero external dependencies beyond standard library `urllib.request`, `json`, `dataclasses`, and `time`. It executes out-of-the-box on any standard Python 3.10+ installation without `pip install`.
</threat_model>
