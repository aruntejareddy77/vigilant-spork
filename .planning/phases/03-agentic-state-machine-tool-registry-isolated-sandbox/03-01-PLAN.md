# Plan 03-01: Agent State Machine Runtime, SQLite Persistence & Human-in-the-Loop (HITL) Gate

## Objective

Build the core agentic runtime for the Sovereign AI Workbench. Implement a self-contained, deterministic `StateGraph` engine supporting multi-step node execution, conditional edges, and a bounded self-correction loop (max 3 retries). Implement `SQLiteCheckpointer` managing `agent_state.sqlite` with Write-Ahead Logging (WAL) for persistent session state and crash-recovery. Implement the `interrupt(payload)` human approval gate pausing graph traversal before critical/final actions, persisting a `SUSPENDED` checkpoint, and resuming upon operator confirmation.

## User Story Framing

**As an** industrial operations engineer or refinery technician,  
**I want** the agent runtime to execute complex multi-step workflows sequentially, persist intermediate progress so multi-turn interactions don't repeat completed steps, automatically correct minor errors, and pause for my explicit approval before generating official deliverables,  
**So that** I have complete oversight, transparency, and crash-resilient autonomy over industrial AI operations.

<threat_model>
### ASVS & STRIDE Threat Modeling

- **OWASP ASVS Category:** V10.3 (Application Integrity), V1.4 (Access Control Architecture).
- **Threat T-03-05 (STRIDE: Elevation of Privilege):** An agent bypasses the human approval gate to autonomously execute sensitive actions or finalize official plant documents without operator sign-off.
  - *Mitigation:* The approval gate is enforced structurally in the `StateGraph` execution loop. Calling `interrupt()` immediately raises `GraphInterrupt`, halts the thread, transitions state to `SUSPENDED`, and rejects any advancement until a cryptographic `APPROVAL_GRANTED` token is registered in the checkpointer and audit ledger.
- **Threat T-03-06 (STRIDE: Denial of Service):** An infinite self-correction loop or circular graph execution consumes unbounded compute threads and database connections.
  - *Mitigation:* The state schema enforces strict `max_steps` (default 25) and `max_retries` (default 3) ceilings. Reaching the limit terminates the loop and forces state transition to `FAILED` / `ERROR_ESCALATION`.
</threat_model>

## Multi-Source Coverage Audit

- **Requirements Covered:**
  - `ORCH-01`: Agent runtime implements a multi-step planner and executor state machine decomposing requests into sequential tool and model invocations (FR-AO-1).
  - `ORCH-02`: Agent maintains and persists session state across multi-turn task iterations without re-executing completed steps (FR-AO-4).
  - `ORCH-03`: System provides a bounded self-correction loop (configurable, default 3 attempts) when tools produce runtime errors (FR-AO-5).
  - `ORCH-04`: System enforces a Human-in-the-Loop (HITL) approval gate pausing graph execution before final deliverable generation and saving state until resumed (FR-AO-6).
- **Locked Decisions Implemented:**
  - `D-28`: Native self-contained StateGraph engine with nodes, edges, conditional branches, and state schemas.
  - `D-29`: Persistent SQLite WAL database (`agent_state.sqlite`) storing thread checkpoints and step logs.
  - `D-31`: Asynchronous `interrupt()` mechanism pausing graph state, storing pending payload, and resuming via API/CLI.
  - `D-34`: Bounded reflection loop (max 3 retries) feeding formatted error tracebacks to the model context.
